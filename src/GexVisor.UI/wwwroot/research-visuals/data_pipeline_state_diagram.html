Key Concepts in This Pipeline

1. Heterogeneous Data Integration

Combining data from multiple sources with different schemas, formats, and access patterns into a unified pipeline.

class SourceAdapter(ABC): @abstractmethod def fetch(self, params) -> DataFrame: pass @abstractmethod def normalize(self, raw) -> DataFrame: pass

2. Multi-Tier Storage

Hot/warm/cold data tiers optimize for different access patterns - frequently used data stays fast, historical data moves to cheaper storage.

def get_data(key): if key in memory_cache: # Hot return memory_cache[key] if key in file_cache: # Warm return file_cache[key] return fetch_from_api(key) # Cold

3. Rate Limiting

External APIs have request limits. Efficient rate limiting prevents wasted requests and handles backpressure gracefully.

from collections import deque class RateLimiter: def __init__(self, max_req, window_sec): self.window = deque(maxlen=max_req) self.window_sec = window_sec

4. Horizontal Partitioning

Splitting large tables by a key (often date) enables parallel processing and efficient queries via partition pruning.

CREATE TABLE events ( id SERIAL, event_date DATE, data JSONB ) PARTITION BY RANGE (event_date); CREATE TABLE events_2024 PARTITION OF events FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');

5. Data Quality Scoring

Quantifiable quality metrics enable automated decisions about data fitness for downstream use.

def quality_score(record): checks = { 'complete': all_fields_present(record), 'valid': values_in_range(record), 'consistent': cross_field_ok(record) } weights = [0.4, 0.35, 0.25] return sum(c*w for c,w in zip(checks.values(), weights))

6. Parallel Processing

For I/O-bound work that fits on one machine, thread pools provide simple parallelism without distributed system complexity.

from concurrent.futures import ThreadPoolExecutor workers = max(2, min(8, cpu_count() - 1)) with ThreadPoolExecutor(workers) as pool: results = list(pool.map(process, items))

Discussion: When to Scale Out?

  • Single-machine parallelism works when data fits in memory and processing is I/O-bound. When would you switch to Spark or similar?
  • Relational databases scale vertically well. At what point do you need horizontal scaling (sharding)?
  • File caching works great for single nodes. What would you use for a distributed deployment?
  • Rate limiting in-process is simple. How would you coordinate limits across multiple workers?
